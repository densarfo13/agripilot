# Product Playbook

How to decide WHAT to build.

## The one question
"Does this help the farmer make today's next best decision?" If no → don't build it.

## Before building
Fill the Feature Manifest (FEATURE_LIFECYCLE.md). If you can't articulate the problem, the persona,
the value, and the success metric, the feature isn't ready.

## North star + KPIs (from the charter)
Farmer Trust · Farmer Productivity · Recommendation Accuracy · Reliability · Pilot Success. A change
that improves none of these is not built.

## Do-not-build (auto-reject without production evidence)
New AI buzzwords · blockchain · new dashboards · speculative ML · new "platforms/meshes" · grand
rewrites of working modules. Architecture expansion requires *measured production evidence* of a real
farmer need — not a bigger spec.

## Honesty over polish
A confident wrong answer harms a farmer more than "I don't know." Evidence-weak → show the setup step
that unlocks value, not invented advice. Market/yield data with no live feed says so — never a fake number.

## Pilot focus
The real blocker is operational (one on-device acceptance run: real scan + GPS, telemetry lit), not
more features or governance. See PRODUCTION_CERTIFICATION.md.
